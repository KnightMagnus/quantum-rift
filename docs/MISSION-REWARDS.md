# Mission rewards

These formulas describe reward calculation, not measured play-session income or evidence that every career pays equally.

- Core cargo (`server/jobs.ts`, `offers`): `(800 + jumps*1100 + tonnes*60)*1.35`, rounded. Travel and cargo size are paid, but time spent docking/refuelling and foregone trading profit are not separately priced. The UI shows jumps and required free hold, not a guaranteed credits-per-minute rate.
- Core bounty: `4000 + target strength*60`, rounded, then the existing combat-rank multiplier `1 + 0.06*rank`. Target strength is a risk proxy; pursuit time is not measured. Stronger targets cannot be described as low danger merely because their system is safe.
- Patrol: `3000 + required kills*1800 + system danger*1500`, rounded. Encounter time is variable. Do not infer a measured rate from the nominal kill count.
- Elite bounty: `45000 + target strength*160`, rounded; its existing rank prerequisite remains. Accepted payouts remain fixed.
- Armada pool (`server/coop.ts`, `coopOffers`): existing `WARBAND.rewardBase + danger*WARBAND.rewardDanger + jumps*4000`, rounded. Only new accepted team contracts divide this one pool exactly by a named consenting roster. Integer remainders are assigned deterministically; total shares equal the pool. The old rounded-per-player rule could theoretically over/under-issue for non-divisible amounts. Existing saved contracts retain their old reward and behavior; no migration changes their promises.
- Event/supply, rescue/survey/salvage, passenger, Syndicate and expedition offers remain owned by their existing modules (`server/living.ts`, `fronts.js`, `syndicate.js`, `arcs.js`, shared Eventide/passenger rules). Their existing acceptance checks and formulas remain unchanged. Buying supply cargo is still the captain's cost, not a hidden full-hold reservation; passenger seats remain separate from crew housing.
- Existing ambient Armada bounty sharing (`shareBounty`) adds rewards on top rather than splitting the victim's one bounty pool. The team planner explicitly distinguishes this from team-contract shares. Vanguard/other existing completion bonuses are not folded into or silently removed from a saved base contract reward.

New board offers carry `offerVersion:1`; accepted offers copy their reward once. Reopening a board, changing filters, gaining rank, another member leaving or reconnecting does not reroll accepted pay. A new team plan is session-only; everyone reviews the current roster/share, then the proposer starts. Refusal revises the roster and clears Ready flags. Disconnect/leave/capacity changes cancel unsafe pending plans without assignment. Accepted shares remain fixed, no late enrollment; offline teammates keep completion and collect normally on return. Abandonment does not redistribute a forfeited share. Duplicate Start and turn-in cannot create additional assignments/credits.

See [ECONOMY-BASELINES.md](ECONOMY-BASELINES.md) for play-session measurement. Synthetic fixtures do not establish observed progression or usability results.
